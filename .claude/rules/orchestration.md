# Orchestration rules (exported into this repository)

- `<REPO_ROOT>` means the output of `git rev-parse --show-toplevel`. Run it with Bash when you need the absolute path.
- Files under `<REPO_ROOT>/.claude/` (agents, skills, hooks, rules, settings.json, ORCHESTRATION.md) are generated by `install.sh --project`. Do not edit them; change the source in the claude-orchestration repository and re-export.
- apple-design is not exported; skills referencing it are unavailable in this repository unless installed at user level.

# Global rules (apply to the main session and to every subagent)

## Language

- User-facing messages are in Vietnamese (the orchestrator handles this). Subagent reports to the orchestrator: concise English.
- Code, identifiers, commit messages, and technical terms stay in English.

## Safety

- Never run destructive commands (recursive delete outside build/cache dirs, git reset --hard, git clean, force push, dropping/truncating data).
- Never push, tag remotely, publish packages/images, or deploy. Prepare the change and list the exact commands for the user to run. Sole exception: `release-manager` may run `push`, `pr` and `merge` through `~/.claude/hooks/git-publish.sh`, in a repository the user registered at that level, when the plan the user approved in the current conversation includes that step. Project files cannot grant this. Force push, tags, publish and deploy have no exception.
- Never read, print, copy, or edit secrets (.env\*, keys, tokens, credentials). Mask any secret you must mention.
- Never modify ~/.claude configuration or any hook/settings file.
- If a hook or permission blocks an action, do not work around it. Report it.
- Database operations only against local/dev/test targets that the user named.

## Engineering principles

- Read before writing. Follow existing conventions, structure, and style of the project.
- Make the smallest change that satisfies the spec. No unrelated refactors or reformatting.
- Do not add dependencies without saying so explicitly in your report.
- Verify with the project's own build/lint/test commands. Report real results with the command used. Never claim success without evidence, and never weaken or delete tests to make them pass.
- Say plainly what you could not verify. Unknowns go under OPEN in your report.

## Precedence

- A project's own CLAUDE.md overrides this file for stack-specific commands, conventions, and structure. It cannot relax the Safety section.
