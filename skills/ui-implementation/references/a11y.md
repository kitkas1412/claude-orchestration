# Accessibility checklist (WCAG 2.2 AA)

Organized by POUR: Perceivable, Operable, Understandable, Robust. The structure and the selection of WCAG 2.2 criteria draw on the accessibility skill in addyosmani/web-quality-skills (MIT, https://github.com/addyosmani/web-quality-skills). The wording here is original. Automated tools catch only part of these issues, so list what still needs manual testing.

## Perceivable

- Images that convey meaning have a text alternative. Decorative images have an empty alt or are hidden from assistive technology (1.1.1).
- Text contrast is at least 4.5:1. Large text (18pt, or 14pt bold, and up) needs 3:1 (1.4.3).
- Non-text contrast is at least 3:1 for UI component boundaries, states and meaningful graphics (1.4.11).
- Color is never the only signal. Pair it with text, an icon or a pattern (1.4.1).
- Content reflows at 320 CSS px width without two-dimensional scrolling and works at 200% text zoom (1.4.10, 1.4.4).
- Layout survives user text spacing overrides without clipping or overlap (1.4.12 Text Spacing).
- Content shown on hover or focus can be dismissed, hovered over, and stays until dismissed (1.4.13).
- Video with speech has captions. Audio-only content has a transcript (1.2.x).

## Operable

- Everything works by keyboard, with no trap. Tab order follows the visual and reading order (2.1.1, 2.1.2, 2.4.3).
- Focus is visible (2.4.7), and a focused element is not entirely hidden by sticky headers, banners or modals (2.4.11 Focus Not Obscured, Minimum).
- Pointer targets are at least 24 by 24 CSS px, or have enough spacing around them (2.5.8). Prefer larger on touch (platform guidance is bigger).
- Any drag interaction has a single-pointer alternative such as buttons or a menu (2.5.7).
- Gestures with paths or multiple points have a simple alternative (2.5.1). Actions fire on release, not press (2.5.2).
- Nothing flashes more than three times per second (2.3.1).
- Best practice, not an AA item (relates to 2.3.3, AAA): respect the reduced-motion preference.
- A skip link or landmarks let users bypass repeated blocks (2.4.1). Pages and sections have descriptive titles and headings (2.4.2, 2.4.6).
- Link purpose is clear from its text or context (2.4.4).

## Understandable

- The page language is set (3.1.1).
- Every input has a programmatic label, not only a placeholder (3.3.2, 1.3.1).
- Errors name the field and say how to fix it, in text (3.3.1, 3.3.3).
- Help mechanisms (contact, chat, help link) appear in the same place across pages (3.2.6 Consistent Help, A).
- Components behave consistently across screens (3.2.3, 3.2.4). Focus or input alone does not trigger a context change (3.2.1, 3.2.2).
- Do not make users re-enter information already provided in the same flow (3.3.7 Redundant Entry).
- Authentication does not depend on a cognitive test such as memorizing or transcribing, and allows paste and password managers (3.3.8).

## Robust

- Use valid, native HTML or the platform's native controls. Add ARIA only when no native element fits, and keep name, role and value correct (4.1.2).
- Status messages (saved, errors, loading done) are announced without moving focus, for example with a live region (4.1.3).
- Custom widgets follow the established keyboard pattern for their role.
- Dialogs move focus in, trap it while modal, and return it to the trigger on close.

## Manual checks to hand to a human

- Tab through the whole flow with no mouse.
- Test with a screen reader on the target platform.
- Zoom to 200% and resize to 320 px.
- Toggle reduced motion and, where relevant, high contrast.
